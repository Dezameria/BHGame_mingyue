# การทดสอบ

สถานะ: ✅ ผ่าน / ❌ ไม่ผ่าน / ⏳ ยังไม่ทดสอบ เขียนวันที่และสภาพแวดล้อม (singleplayer หรือ dedicated, ping เท่าไร) ทุกครั้ง

## ตั้งเซิร์ฟ + client สองตัวในเครื่องเดียว

1. `./gradlew.bat runServer` ครั้งแรกจะสร้าง `run/eula.txt` แล้วปิดเอง **ผู้ใช้ต้องแก้เป็น `eula=true` เอง** (เป็นการยอมรับข้อตกลงของ Minecraft) — ทำแล้ว 2026-10-19
   - เตรียมไว้แล้ว (2026-10-19): `run/server.properties` มี `online-mode=false` (เซิร์ฟจะเติมค่าอื่นเองตอนเปิด) และ `run/ops.json` ให้ op level 4 กับ `Dev` และ `Player2` (UUID แบบ offline คำนวณจาก `"OfflinePlayer:" + ชื่อ`) ทั้งสองไฟล์อยู่ใน `run/` ซึ่งไม่ขึ้น git
   - ชื่อ `Dev` เป็นชื่อเริ่มต้นของ `runClient` ใน ForgeGradle **ยังไม่ได้ยืนยัน** ถ้า client แรกเข้าเซิร์ฟด้วยชื่ออื่น (ดูบรรทัด `... joined the game` ใน console) ให้พิมพ์ `op <ชื่อ>` ที่ console แทน
2. เปิด `./gradlew.bat runServer` อีกครั้งแล้วรอจนขึ้น `Done`
3. client ตัวแรก: `./gradlew.bat runClient` (โฟลเดอร์ `run/`)
4. client ตัวที่สอง: `./gradlew.bat runClient2` (โฟลเดอร์ `run2/`, ชื่อ `Player2`) เปิดในอีกหน้าต่าง terminal
5. ทั้งสองตัวเข้า Multiplayer → Direct Connection → `localhost`
6. ทั้งสองตัวเป็น op อยู่แล้ว (จาก `run/ops.json`) ใช้ `/gamemode`, `/give` และ `/bhgame debug` ได้เลย

หมายเหตุ: server และ client สองตัวใช้ RAM รวมกันมาก (gradle ตั้ง `-Xmx3G` ต่อ build) ถ้าเครื่องไม่พอให้ปิดโปรแกรมอื่นก่อน

## วิธีจำลอง ping บน Windows

ใช้โปรแกรม **clumsy** (ปรับ lag ขาเข้าและขาออก) กับ port ของ dedicated server ที่รันในเครื่อง ทดสอบอย่างน้อยที่ 0ms, 100ms และ 200ms

## ทดสอบโหลด (ก่อนปล่อย P7 และทุกครั้งที่แก้ network หรือ session)

ใช้ spark วัด และกฎอยู่ใน [`multiplayer-performance.md`](multiplayer-performance.md)

| รายการ | เกณฑ์ | สถานะ |
| :--- | :--- | :--- |
| วาง training block 300 อันใน chunk ที่โหลดอยู่ ไม่มีคนเล่น | MSPT ไม่เพิ่มขึ้นเลย (block entity ไม่ tick) | ⏳ |
| `/bhgame stress 70` (session จำลองเท่าจำนวนผู้เล่นเซิร์ฟจริง) | MSPT เพิ่มไม่เกิน 0.5ms | ⏳ |
| `/bhgame stress 150` (เผื่อเซิร์ฟโตขึ้นเท่าตัว) | MSPT เพิ่มไม่เกิน 1ms | ⏳ |
| session จริงหลายตัวพร้อมกัน (หลาย client) | packet ของ mod ต่อ session ตรงกับประมาณการใน `multiplayer-performance.md` (~1.5–5 ต่อวินาที) | ⏳ |
| คน 10+ คนพลาดพร้อมกันในลานเดียว (`burst`, `strikeVisual`, ไฟ) | FPS ของคนในลานตกไม่เกิน 15%, คนยืนดูไม่โดน damage | ⏳ |
| เล่น/ยกเลิกซ้ำ 200 รอบ | heap หลัง GC ไม่โตขึ้นเรื่อยๆ, session ค้าง = 0 | ⏳ |
| client ยืนดูหญ้า 300 ต้น | FPS ตกไม่เกิน 10% เทียบกับไม่มีหญ้า | ⏳ |
| เซิร์ฟ lag จนเหลือ 10 TPS | เกมช้าลงพร้อมกันแต่ยังตัดสินถูก ไม่มีการพลาดเอง | ⏳ |

## เกมอื่น

เพิ่ม checklist ละเอียดตอนเริ่มทำแต่ละเกม (ดู [`adding-a-minigame.md`](adding-a-minigame.md)) จุดเสี่ยงที่รู้อยู่แล้ว:

| เกม | จุดที่ต้องทดสอบเป็นพิเศษ | สถานะ |
| :--- | :--- | :--- |
| `polarity_grass` | ผู้เล่นใหม่สับสนเรื่องการจับคู่สีกับปุ่มไหม | ⏳ |
| `thunder_grass` | ค้าง `LMB` แล้วกด `SPACE` พร้อมกันได้สบายไหม | ⏳ |
| `wooden_dummy` | ตัวเลขความยาวชุดและเวลา: Difficulty 1 คนทั่วไปผ่านได้, Difficulty 3 ต้องซ้อม | ⏳ |
| `wind_listener` | แยกซ้าย/ขวาด้วยหูฟังได้ชัด, ลมจากด้านบนแยกได้ด้วยเสียงที่ต่างกัน, subtitle ไม่บอกทิศ | ⏳ |
| `wind_listener` | คนภายนอกเห็นผ้าปิดตาบนหัว (รวมผู้เล่นที่ใส่หมวกอยู่) | ⏳ |
| `candle_altar` | สแกนเทียนได้ถูก (ไม่นับเทียนที่ติดไฟอยู่แล้ว, ตัดเทียนที่ถูกบัง), เทียนจริงไม่ติดไฟบนจอคนอื่น | ⏳ |
| `candle_altar` | ยิงโดนง่ายพอที่ ping 200ms, คนโกงส่ง yaw/pitch ปลอมไม่ได้ผล | ⏳ |
| `candle_altar` | หาเทียนด้านหลังเจอด้วยเสียงไฟลุก | ⏳ |

## ทุกครั้งก่อนปล่อย

| รายการ | สถานะ |
| :--- | :--- |
| เล่นได้โดยไม่มี bhfx | ⏳ |
| เล่นได้โดยไม่มี playerAnimator (ท่าทางเป็นแบบ fallback) | ⏳ |
| ท่าทางแสดงถูกต้องเมื่อผู้เล่นอยู่ใน battle mode ของ Epic Fight | ⏳ |
| dedicated server เปิดได้ (ไม่มี class ฝั่ง client หลุดไปโหลดบน server) | ⏳ |
| `en_us` และ `th_th` ไม่มี key หาย | ⏳ |
