# หาบน้ำ (`water_yoke`)

**สถานะ:** 📝 ออกแบบ (2026-10-22) — แบบแบกเดินไปไหนก็ได้ (D48) กระโดดได้ (D49) วิ่งได้ (D50) ยังไม่มีโค้ด

## แนวคิด
คานหาบกับถังน้ำสองใบที่วางอยู่ในโลก ผู้เล่นยกขึ้นบ่าแล้ว **เดินไปไหนก็ได้ตามปกติ** ระหว่างแบก น้ำในถังกระฉอกตามจังหวะก้าว ต้องคอยทรงตัวไม่ให้หก ถึงที่หมายแล้ววางลงตรงไหนก็ได้ เป้าหมายหลักคือ **ให้การแบกน้ำเดินไปมาเป็นส่วนหนึ่งของโรลเพล** (ตักน้ำจากบ่อไปเติมโอ่งในสำนัก) โดยมีมินิเกมเล็กๆ ให้เล่นระหว่างทาง

### ทำไมเอากลับมาได้ (เดิมตัดใน D10)
ปัญหาเดิมคือใช้ WASD ทั้งเดินและเล่นเกม พอหันกล้องแล้วทิศเปลี่ยน แบบนี้ **WASD กับเมาส์ใช้เดินและหันตามปกติของ vanilla ทั้งหมด** ส่วนการทรงตัวย้ายไปใช้ `LMB`/`RMB` ไม่มีปุ่มไหนใช้สองหน้าที่ (`SPACE` เป็นกระโดดตามปกติ) ดู D48, D49

## รูปแบบ
- **ประเภท:** **Carry** (ใหม่, ไม่ใช่ทั้ง Herb และ Station) บล็อกถูกยกออกจากโลกตอนเริ่ม และถูกวางคืนตอนจบ
- **หน้าตาบล็อก:** คานหาบพาดอยู่บนถังไม้สองใบที่วางบนพื้น ระดับน้ำในถังแสดงด้วย blockstate `water=0..3` (เปลี่ยนเฉพาะตอนวาง ไม่เปลี่ยนระหว่างเล่น)
- **ข้อมูลในบล็อก:** block entity เก็บ `Water` (0–3, ค่าเริ่มต้น 3) + NBT ปกติ (`Difficulty`) ข้อมูลติดไปกับตัวเมื่อยกและกลับมาเมื่อวาง
- **ปุ่ม:**
  - WASD + เมาส์ = เดินและหันตามปกติ
  - `LMB` = ยกฝั่งซ้าย, `RMB` = ยกฝั่งขวา (ตามตาราง `InputKey` ของ core: `LMB` ปัดซ้าย / `RMB` ปัดขวา)
  - `SPACE` = กระโดดตามปกติ (ไม่ใช่ปุ่มของเกม) แต่ลงพื้นแล้วถังส่ายแรง (ดู Pattern)
  - ปุ่มยกเลิก (`Backspace`) = **วางลง**
- **ค่าเริ่มต้น:** ไม่มี HP ไม่มี `TimeLimit` (แบกได้นานเท่าไรก็ได้) ไม่ใช้ `MaxMistakes` ระดับน้ำคือชีวิต
- **Gauge:** ไม่มี
- **Input profile:** `keys=[LMB, RMB]`, `holdKeys=[]`, `camera=FREE`, `crosshair=false`, `sendIdlePresses=false`, `aimPayload=false`, `movement=FREE` (ใหม่: เดิน วิ่ง และกระโดดตามปกติ)
- **Channel:** `BODY` (ใหม่) คานกับถังวาดในมุมบุคคลที่หนึ่งแทนมือ
- **ท่าทางที่คนภายนอกเห็น (`PlayerPose`):** `CARRY_YOKE` (ใหม่, ไม่ย่อตัว) สองมือจับคานบนบ่า + **ของประกอบ: คานกับถังสองใบ** (layer ฝั่ง client จากสถานะ pose) ระดับน้ำในถังของ layer ส่งไปพร้อม pose (`S2CPlayerPose` มีค่าเพิ่ม 1 byte ส่งเฉพาะตอนระดับน้ำเปลี่ยน) ขาเดินด้วย animation เดินของ vanilla fallback: เดินธรรมดา ไม่มีคาน
- **คำใบ้ตอนเริ่ม:** "ถังเต็มเสมอขอบ… ก้าวให้มั่น อย่าให้หก"

## วงจรการเล่น
1. **ยก:** คลิกขวาที่บล็อก (ระยะเริ่มแบบหญ้า: ยืนติดบล็อก) → ช่วง `FOCUS` 2 วินาทีเป็นท่าย่อตัวยกคานขึ้นบ่า (ผู้เล่นขยับไม่ได้) → บล็อกถูกลบออกจากโลก
2. **แบก:** เดินไปไหนก็ได้ cue มาเรื่อยๆ ตามการเคลื่อนที่ (Pattern ด้านล่าง)
3. **เติมน้ำ:** ยืนในน้ำตื้น (น้ำ source ที่เท้า แต่หัวไม่จม) → ถังเต็ม 3 ขั้น พร้อมเสียงตักน้ำ (server ตรวจทุก 5 tick)
4. **วาง:** กดปุ่มยกเลิก → ช่วงวาง 1 วินาที (ขยับไม่ได้) → บล็อกถูกวางที่ช่องหน้าผู้เล่น ถ้าวางไม่ได้ (ไม่มีพื้นหรือมีของขวาง) ลองช่องที่เท้า ถ้ายังไม่ได้ขึ้น action bar "ตรงนี้วางไม่ได้" แล้วแบกต่อ
   - **วางข้างหม้อ cauldron** ที่ว่างหรือยังไม่เต็ม: เทน้ำใส่ (ไอเดีย ดูคำถามเปิด)

## Pattern
ใช้ `BeatTrack` สำหรับ cue (TAP + FEINT) ความถี่ขึ้นกับ **สถานะการเคลื่อนที่** ที่ session คำนวณจากตำแหน่งบน server ทุก 5 tick แล้วให้ pattern อ่านผ่าน `PatternContext.motion()` (pattern ห้ามแตะ `ServerPlayer`)

| Cue | ชนิด | ปุ่ม | สิ่งที่เห็น (คนเล่น) | ความหมายในเรื่อง |
| :--- | :--- | :--- | :--- | :--- |
| **เอียง** | `TAP` | `LMB` (ซ้ายตก) / `RMB` (ขวาตก) | คานเริ่มเอียง ถังฝั่งนั้นห้อยต่ำลง ผิวน้ำเอียงตาม | ยกฝั่งที่ตกขึ้นมา |
| **ลมเล่น** | `FEINT` | (ห้ามกด) | ผิวน้ำเป็นระลอก ถังสั่นเล็กน้อยแต่ **คานไม่เอียง** | แก้ตอนนี้ = แก้เกินเหตุ น้ำหกเอง |

| สถานะ | Cue | ระยะห่างระหว่าง cue (tick, Difficulty 1 / 2 / 3) | กรอบเวลา (tick, 1 / 2 / 3) |
| :--- | :--- | :--- | :--- |
| **ยืนนิ่ง** | ไม่มี cue (พักได้, AFK ได้, เปิดแชทได้โดยไม่หก) | — | — |
| **เดิน** | เอียง 75%, ลมเล่น 25% | 28 / 24 / 20 | เอียง 14 / 11 / 8, ลมเล่น 16 / 14 / 12 |
| **วิ่ง** (ส่ายหนัก) | เอียง 45%, **เอียงคู่** 40% (ห่างกัน 6 tick), ลมเล่น 15% | 16 / 14 / 12 | เอียง 11 / 9 / 6, ลมเล่น 14 / 12 / 10 |
| **เดินนาน** (เคลื่อนที่ต่อเนื่องทุก 20 วินาที วิ่งนับเร็วเป็น 2 เท่า) | เพิ่ม **เอียงคู่** (ซ้ายแล้วขวาห่างกัน 8 tick) | ระยะห่าง −2 tick ต่อขั้น สูงสุด 3 ขั้น | แถว "เดิน" หรือ "วิ่ง" ลบ 1 tick ต่อขั้น (ไม่ต่ำกว่า 4 tick) |

- หยุดเดินเกิน 3 วินาที = ความล้ารีเซ็ตกลับเป็น "เดิน" ธรรมดา ผู้เล่นจึงเลือกได้ว่าจะเดินยาวแบบเสี่ยงหรือพักเป็นช่วงๆ
- **วิ่ง:** ถึงเร็วแต่ส่ายหนัก เปลี่ยนจากเดินเป็นวิ่งมีผลตั้งแต่ cue ถัดไป ระหว่างวิ่งถังในมุมบุคคลที่หนึ่งแกว่งกว้างขึ้นตลอดเวลา (แค่ภาพ ไม่ใช่ cue) วิ่งแล้วกระโดดยังได้ส่ายแรงตอนลงพื้นตามปกติ
- cue ที่ส่งไปแล้วยังนับตามเดิมแม้จะหยุดเดิน (ไม่ยกเลิก cue กลางคัน)
- **เหตุการณ์บังคับ** (session แจ้ง pattern ทันที ไม่รอจังหวะ):
  - **กระโดดแล้วลงพื้น = ส่ายแรง:** ทันทีที่ลงพื้น ส่ง **เอียงคู่** (ฝั่งแรกสุ่ม ฝั่งที่สองตรงข้าม ห่างกัน 6 tick) กรอบเวลาแคบกว่าปกติ 2 tick (ไม่ต่ำกว่า 4 tick) ระหว่างลอยอยู่กลางอากาศไม่มี cue ใหม่ (cue ที่ส่งไปแล้วยังนับ)
    - กระโดดซ้ำก่อนแก้ส่ายรอบก่อนเสร็จ: ส่ายรอบใหม่ต่อท้ายรอบเดิม (ค้างได้สูงสุด 2 รอบ เกินนั้นไม่เพิ่ม) กระโดดรัวๆ จึงหกง่ายมาก
    - ตกจากที่สูงเกิน 2 บล็อก: หกหนึ่งขั้นทันที แล้วตามด้วยส่ายแรง
  - **ก้าวลงบล็อกโดยไม่กระโดด** (ตกต่ำกว่าครึ่งบล็อก): **เอียง** หนึ่งครั้งทันที ฝั่งสุ่ม
  - **โดนตี** (damage จากอะไรก็ได้): น้ำหกหนึ่งขั้นทันที ไม่มี cue ให้แก้
- ไม่สุ่มลมเล่นติดกันเกิน 2 ครั้ง และไม่สุ่มเอียงฝั่งเดิมเกิน 3 ครั้งติด
- **ถังว่าง (`Water` = 0):** cue หยุด แบกต่อได้ (เดินกลับไปเติมน้ำ) ไม่จบ session

## ผลลัพธ์และบทลงโทษ
session จบเมื่อวางลง ผลตัดสินจากระดับน้ำตอนวาง เทียบกับตอนยกหรือตอนเติมน้ำครั้งล่าสุด

| Outcome | เงื่อนไข |
| :--- | :--- |
| `PERFECT` | วางโดยน้ำไม่ลดเลย (และ `Water` > 0) |
| `SUCCESS` | วางโดยยังมีน้ำเหลือ แต่หกไปบ้าง |
| `FAIL` | วางตอนถังว่าง |
| `ABORTED` | จบแบบผิดปกติ (ด้านล่าง) |

- **หกหนึ่งขั้น** (กดไม่ทัน, กดผิดฝั่ง, กดตอนลมเล่น, โดนตี): particle `SPLASH` เล็กน้อยจากถังฝั่งนั้น (คนรอบข้างเห็น) ไม่มี damage
- **ถังว่าง:** `effect(SLOWNESS, 100, 0)` หนึ่งครั้ง ("ไหล่ล้า") ไม่มีบทลงโทษใหญ่ เพราะเกมนี้เป็นกิจวัตร ไม่ใช่การทดสอบ
- **ไม่มีของรางวัล** (ไม่มี loot table) ผลลัพธ์ลง log และ scoreboard ตาม core หัวข้อ 12 และเพิ่ม `bhg_water_carried` (นับครั้งที่วางโดยมีน้ำ)
- **ทุบตรงๆ:** บล็อกไม่พัง (`BruteForce=KEEP`) ไม่มีบทลงโทษ admin ลบได้ในโหมด creative
- **จบแบบผิดปกติ** (ตาย, ออกเซิร์ฟ, เปลี่ยนมิติ, ถูก teleport ไกล, ว่ายน้ำ/หัวจม, ขึ้นพาหนะ, ใช้ elytra, `/bhgame abort`): **ถังไม่หาย** วางบล็อกที่ตำแหน่งผู้เล่น (ระดับน้ำตามที่เหลือ) ถ้าวางไม่ได้ drop เป็น item ที่มี NBT ของบล็อก (`BlockEntityTag`) ผลเป็น `ABORTED`

## การแสดงผล
- **คนเล่นเห็น (มุมบุคคลที่หนึ่ง, diegetic):** คานพาดขวางด้านล่างจอแทนมือ ถังสองใบห้อยอยู่ขอบจอซ้ายขวา โยกเบาๆ ตามจังหวะก้าว
  - เอียง: คานหมุนช้าๆ ไปทางฝั่งที่ตก (telegraph ตั้งแต่ `leadTicks`) ผิวน้ำเอียงตาม
  - ส่ายแรง (หลังลงพื้น): คานยุบลงแล้วเหวี่ยงซ้ายขวา น้ำกระเพื่อมสูงกว่าเอียงปกติ
  - ลมเล่น: ระลอกบนผิวน้ำ + ใบไม้ปลิวผ่านหน้าจอหนึ่งใบ
  - กดถูก: คานกลับมาตรงทันที (feedback ฝั่ง client)
  - หก: น้ำกระฉอกออกจากถัง ระดับน้ำลดลงหนึ่งขั้น
- **HUD:** ไม่มี
- **เสียง (เฉพาะคนเล่น):** ไม้คานลั่นเอี๊ยดตอนเอียง, น้ำกระฉอกตอนลงพื้น, ลมหวีดตอนลมเล่น
- **คนภายนอกเห็น:** ผู้เล่นแบกคานหาบเดินไปมาตามปกติ กระโดดแล้วน้ำกระเซ็นง่าย ระดับน้ำในถังลดลงเมื่อหก น้ำกระเซ็นตอนพลาด ตอนยกและวางเห็นท่าย่อตัว
- **bhfx / fallback:** ไม่ใช้

## คำถามที่ยังเปิดอยู่
1. **เทน้ำใส่ cauldron:** วางข้าง cauldron แล้วเทน้ำใส่ให้เป็นน้ำ (เปลี่ยนบล็อกตอนจบ ไม่ใช่ระหว่างเล่น) ใช้เป็นงานโรลเพลส่งน้ำได้ ทำเลยไหม
2. **บันได/เถาวัลย์:** ปีนได้ไหมระหว่างแบก (vanilla ปิดยาก) หรือปล่อยให้ปีนได้แต่ทุกขั้นเป็น cue เอียง
3. **เปิด inventory ระหว่างแบก:** อนุญาตไหม (ตอนเปิดผู้เล่นยืนนิ่ง จึงไม่มี cue)
4. **Epic Fight battle mode:** บังคับกลับโหมดปกติตอนยกหรือไม่ (`LMB`/`RMB` ถูกดักอยู่แล้ว)
5. **ปุ่มเอียง:** กดฝั่งที่ **ตก** (ร่างนี้) หรือกดฝั่ง **ตรงข้าม** ต้องลองเล่นจริง
