# หาบน้ำ (`water_yoke`)

**สถานะ:** 📝 ออกแบบ (2026-10-29) — ยกและวางแบบ Carry On, เติมน้ำด้วย `water_bucket`, วาดด้วย vanilla ทางเดียว (D51) ตักน้ำออกได้ ปุ่มถ่วงฝั่งตรงข้าม (D52) เดินไปไหนก็ได้ (D48) กระโดดได้ (D49) วิ่งได้ (D50) — 🔨 session รุ่นแรก (2026-10-29, D54) build ผ่าน ยังไม่ได้ลองในเกม

## แนวคิด
หาบน้ำ (คานพาดบนถังไม้สองใบ) เป็นบล็อกที่วางอยู่ในโลก ผู้เล่นยกขึ้นบ่าด้วยมือเปล่าแบบ Carry On แล้ว **เดินไปไหนก็ได้ตามปกติ** ระหว่างแบก น้ำในถังกระฉอกตามจังหวะก้าว ต้องคอยทรงตัวไม่ให้หก ถึงที่หมายแล้ววางลงตรงไหนก็ได้ เป้าหมายหลักคือ **ให้การแบกน้ำเดินไปมาเป็นส่วนหนึ่งของโรลเพล** (ตักน้ำจากบ่อไปเติมโอ่งในสำนัก) โดยมีมินิเกมเล็กๆ ให้เล่นระหว่างทาง

### ทำไมเอากลับมาได้ (เดิมตัดใน D10)
ปัญหาเดิมคือใช้ WASD ทั้งเดินและเล่นเกม พอหันกล้องแล้วทิศเปลี่ยน แบบนี้ **WASD กับเมาส์ใช้เดินและหันตามปกติของ vanilla ทั้งหมด** ส่วนการทรงตัวย้ายไปใช้ `LMB`/`RMB` ไม่มีปุ่มไหนใช้สองหน้าที่ (`SPACE` เป็นกระโดดตามปกติ) ดู D48, D49

## รูปแบบ
- **ประเภท:** **Carry** (ใหม่, ไม่ใช่ทั้ง Herb และ Station) บล็อกถูกยกออกจากโลกตอนเริ่ม และถูกวางคืนตอนจบ ข้อมูลระหว่างแบกอยู่ใน session ของผู้เล่น ไม่มี item ใน inventory (D51)
- **หน้าตาบล็อก:** คานหาบพาดอยู่บนถังไม้สองใบที่วางบนพื้น blockstate `facing` (4 ทิศ ตามทิศที่ผู้เล่นหันตอนวาง) + `water_left=0..3` + `water_right=0..3` (64 state) ระดับน้ำเห็นจากผิวน้ำในถังแต่ละใบ
- **ข้อมูลในบล็อก:** block entity เก็บ NBT ปกติ (`Difficulty`) ระดับน้ำอยู่ใน blockstate ข้อมูลติดไปกับตัวเมื่อยกและกลับมาเมื่อวาง
- **ได้บล็อกมาอย่างไร:** item ของบล็อก (`bhgame:water_yoke`) วางได้ตามปกติ ถังว่างทั้งสองใบ **ไม่มีสูตรคราฟต์** admin แจกหรือวางเอง (D52)
- **ปุ่ม:**
  - WASD + เมาส์ = เดินและหันตามปกติ
  - ค้าง `LMB` = ดันเข็มบนแถบสมดุลไปซ้าย, ค้าง `RMB` = ดันไปขวา ใช้ **ถ่วงฝั่งตรงข้ามกับฝั่งที่ตก** (ขวาตก → `LMB`, ซ้ายตก → `RMB`) (D52, D55)
  - `SPACE` = กระโดดตามปกติ (ไม่ใช่ปุ่มของเกม) แต่ลงพื้นแล้วถังส่ายแรง (ดู Pattern)
  - ~~`Shift` + `RMB` ที่บล็อก = วางลงตรงนั้น~~ (D56) **ปุ่มทิ้งของ (`Q`) = วางลง** ตรงบล็อกที่มองอยู่ (ถ้าไม่ได้มองบล็อก วางข้างหน้า) `RMB` เป็นปุ่มทรงตัวเสมอแม้ย่อตัวอยู่
  - ปุ่มยกเลิก (`Backspace`) = วางลงช่องหน้าผู้เล่น
- **ค่าเริ่มต้น:** ไม่มี HP ไม่มี `TimeLimit` (แบกได้นานเท่าไรก็ได้) ไม่ใช้ `MaxMistakes` ระดับน้ำคือชีวิต
- **Gauge:** ไม่มี
- **Input profile:** `keys=[LMB, RMB]`, `holdKeys=[LMB, RMB]` (D55), `camera=FREE`, `crosshair=true` (ใช้เล็งตอนวาง), `sendIdlePresses=false`, `aimPayload=false`, `movement=FREE` (ใหม่: เดิน วิ่ง และกระโดดตามปกติ)
- **Channel:** `BODY` (ใหม่) คานกับถังวาดในมุมบุคคลที่หนึ่งแทนมือ
- **ท่าทางที่คนภายนอกเห็น (`PlayerPose`):** `CARRY_YOKE` (ใหม่) ดูหัวข้อการแสดงผล
- **คำใบ้ตอนเริ่ม:** "ถังเต็มเสมอขอบ… ก้าวให้มั่น อย่าให้หก"

## วงจรการเล่น
1. **เติมน้ำ (ตอนวางอยู่):** ถือ `water_bucket` แล้วคลิกขวาที่หาบ → ถังฝั่งที่คลิกโดน +1 ขั้น (ถังละ 1 ขั้น, D52) ได้ `bucket` เปล่าคืน พร้อมเสียงเทน้ำ ถ้าฝั่งนั้นเต็มแล้วเติมอีกฝั่ง ถ้าเต็มทั้งคู่ไม่เกิดอะไร (เต็มทั้งหมดใช้ 6 ถัง) ฝั่งซ้ายขวาวัดจากจุดที่คลิกเทียบกับ `facing` ไม่ใช่ session ไม่มี cue
   - **ตักน้ำออก (ส่งน้ำ):** ถือ `bucket` เปล่าคลิกขวาที่หาบ → ถังฝั่งที่คลิกโดน −1 ขั้น ได้ `water_bucket` (ถ้าฝั่งนั้นว่างตักอีกฝั่ง ถ้าว่างทั้งคู่ไม่เกิดอะไร) น้ำเข้าเท่าไรออกเท่านั้น ไม่เพิ่มเอง แล้วเอาถังน้ำไปเทใส่ cauldron หรือที่ไหนก็ได้ตามปกติของ vanilla (D52)
2. **ยก:** มือหลักและมือรองว่างทั้งคู่ กด `Shift` + คลิกขวาที่หาบ (ระยะเริ่มแบบหญ้า: ยืนติดบล็อก) → ช่วง `FOCUS` 2 วินาทีเป็นท่าย่อตัวยกคานขึ้นบ่า (ผู้เล่นขยับไม่ได้) → บล็อกถูกลบออกจากโลก ถ้ามือไม่ว่าง action bar ขึ้น "ต้องวางของในมือก่อน" ยกหาบที่ถังว่างทั้งคู่ได้ (แบกไปเติมที่อื่น) แต่ไม่มี cue
3. **แบก:** เดินไปไหนก็ได้ cue มาเรื่อยๆ ตามการเคลื่อนที่ (Pattern ด้านล่าง)
   - **มือต้องว่างตลอด:** client ล็อกการเลื่อน hotbar, ปุ่มสลับมือ (`F`), ปุ่มทิ้งของ (`Q`) และ **ไม่ให้เปิด inventory** (ยกเลิก `ScreenEvent.Opening` ของ `InventoryScreen` ระหว่างแบก) (D52) server ยังตรวจทุก 5 tick ถ้ามือหลักหรือมือรองมีของ (เช่น เก็บของจากพื้นเข้าช่องที่เลือกอยู่) = จบแบบผิดปกติ
     - ของที่เก็บจากพื้นระหว่างแบกเข้าช่องที่เลือกอยู่ได้ จึงให้ server ข้ามช่องนั้นตอนเก็บของ (ถ้าทำง่าย) ไม่อย่างนั้นยอมให้จบแบบผิดปกติแล้ววางหาบ
   - **บันได/เถาวัลย์ (รุ่นแรก):** ปีนได้ตามปกติ นับเป็นสถานะ "เดิน" (ดูแผนเผื่อใช้ใน Pattern)
4. **วาง:** ~~`Shift` + `RMB`~~ `Q` (D56) ขณะมองบล็อก → วางบนบล็อกนั้น (ต้องอยู่ในระยะ reach ปกติ ช่องต้องว่างและมีพื้นตัน) หรือกดปุ่มยกเลิก → วางช่องหน้าผู้เล่น ถ้าไม่ได้ลองช่องที่เท้า → ~~ช่วงวาง 1 วินาที (ขยับไม่ได้)~~ (รุ่นแรกวางทันที D54) → บล็อกกลับมาในโลกพร้อมระดับน้ำที่เหลือ หันไปทางเดียวกับผู้เล่น
   - **วางห่างจากจุดที่ยกไม่ถึง 3 บล็อก** (หรือวางระหว่างช่วงยก) = `ABORTED` ไม่ได้ `PERFECT` ฟรี (D54) ถ้าวางไม่ได้ขึ้น action bar "ตรงนี้วางไม่ได้" แล้วแบกต่อ

## Pattern (แถบสมดุล, D55)
~~แบบ cue `TAP`/`FEINT` ด้วย `BeatTrack` (เอียง / ลมเล่น / เอียงคู่)~~ แทนด้วย **แถบสมดุล** ตามที่ผู้ใช้ขอ (2026-10-29, D55)

- **แถบ:** gauge 0 (`Gauge.FLAG_BALANCE`) 0.5 = คานตรง เข้าใกล้ 1 = ถังขวาตก เข้าใกล้ 0 = ถังซ้ายตก เข็มแดงบนแถบคือจุดที่คานเอียงไป ต้องเลี้ยงให้อยู่ตรงกลาง
- **ปุ่ม (ค้าง):** ค้าง `LMB` = ดันเข็มไปซ้าย, ค้าง `RMB` = ดันไปขวา (ขวาตกต้องค้าง `LMB`, ตรงกับ D52) ความเร็ว 0.04 ต่อ tick แรงกว่าแรงเอียงที่แรงที่สุดเสมอ จึงแก้ทันได้ทุกครั้งถ้าตอบไว ค้างนานเกินไปเข็มเลยไปอีกฝั่งได้
- **น้ำหนักน้ำ (D56):** ถังสองข้างไม่เท่ากัน = เข็มถูกดึงไปฝั่งที่หนักกว่า **ตลอดเวลา** 0.004 ต่อ tick ต่อระดับที่ต่างกัน แม้ยืนนิ่ง ต้องคอยเลี้ยงตลอด (แรงดึง + แรงเอียงรวมกันไม่เกิน 0.036 ต่อ tick ปุ่มยังแก้ทันเสมอ)
- **แรงเอียง:** ระหว่างเดินหรือวิ่ง สุ่มแรงเอียงใหม่เป็นช่วงๆ ฝั่งสุ่ม บางครั้งเบาบางครั้งหนัก ~~ถังเท่ากัน 25% ของช่วงเป็น **ช่วงนิ่ง** (D56)~~ **ไม่มีช่วงนิ่ง** เดินแล้วต้องเลี้ยงตลอด (D70)
- **แถบแดง (D70):** ปลายแถบข้างละ 30% (`Gauge.BALANCE_DANGER`) ถ้าเข็มอยู่ในแดง **ระหว่างเดินหรือวิ่ง**: แรงเอียง ×1.5, ถูกดึงออกไปทางขอบอีก 0.006 ต่อ tick (รวมแล้วยังไม่เกิน 0.036 ค้างปุ่มยังดึงกลับได้เสมอ) และช้าลงเพิ่ม (ด้านล่าง) ยืนนิ่งในแดงไม่โดน
- **ติด slow ตอนแบก (D70):** แบกหาบที่มีน้ำ = ความเร็วลด 15% (ประมาณ Slowness I) เข็มในแดงระหว่างเคลื่อนที่ = ลด 45% (ประมาณ Slowness III) ถังว่าง = ไม่ช้า ใช้ attribute modifier ของ mod เอง (ไม่มีไอคอน ไม่ทับ slowness จาก potion) เอาออกตอนจบทุกทาง **slow ไม่ทำให้แกว่งน้อยลง** แรงเอียงขึ้นกับว่าเดินอยู่ไหม ไม่ขึ้นกับความเร็ว (เกณฑ์ยืนนิ่ง: เคลื่อนที่ไม่ถึง 0.08 บล็อกใน 5 tick ย่อเดินตอนช้าสุดยังนับว่าเดิน)

| สถานะ | ช่วงละ (tick) | แรงเบา / หนัก ต่อ tick (Difficulty 1 / 2 / 3) | โอกาสหนัก |
| :--- | :--- | :--- | :--- |
| **ยืนนิ่ง** | — | ไม่มีแรงเอียงสุ่ม ไม่ช้าเพิ่มแม้อยู่ในแดง ถังเท่ากัน: เข็มค่อยๆ กลับเข้ากลางเอง (0.006 ต่อ tick) พักได้ AFK ได้ / ถังไม่เท่ากัน: ยังถูกน้ำหนักดึงอยู่ ต้องเลี้ยง | — |
| **เดิน** | 30–70 | เบา 0.005 / 0.007 / 0.009, หนัก 0.012 / 0.016 / 0.020 (สุ่ม ±20%) | 30% |
| **วิ่ง** | 20–45 | เดิน × 1.6 | 50% |
| **ความล้า** (ทุก 20 วินาทีที่เคลื่อนที่ วิ่งนับ 2 เท่า, สูงสุด 3 ขั้น, ยืนนิ่ง 3 วินาทีรีเซ็ต) | เท่าเดิม | +15% ต่อขั้น | +10% ต่อขั้น |

- แรงเอียงไม่เกิน 0.032 ต่อ tick ทุกกรณี เปลี่ยนจากเดินเป็นวิ่งหรือหยุดเดิน = สุ่มแรงใหม่ทันที ลอยกลางอากาศคงแรงเดิม
- **ถึงขอบ = น้ำหกหนึ่งขั้นจากฝั่งนั้น** แล้วเข็มกลับมาตรงกลาง สงบ 1 วินาทีก่อนเริ่มเอียงใหม่ ฝั่งที่ว่างแล้วหกซ้ำไม่ได้ (หกอีกฝั่งแทน)
- **เหตุการณ์บังคับ** (session แจ้ง pattern ทันที):
  - **กระโดดแล้วลงพื้น:** เข็มกระตุก 0.18 ไปทางที่เอียงอยู่ (ตรงกลางพอดี = สุ่มฝั่ง) กระโดดรัวๆ จึงหลุดขอบง่าย
  - **ก้าวลงบล็อก:** กระตุก 0.10
  - **ตกเกิน 2 บล็อก:** หกหนึ่งขั้นทันที แล้วกระตุก 0.25
  - **โดนตี** (ไม่นับ damage จากการตก): หกหนึ่งขั้นทันที
- **ถังว่างทั้งคู่:** เข็มหยุดตรงกลาง แบกต่อได้ ไม่จบ session
- **Packet:** เข็มเคลื่อนที่ด้วยความเร็วคงที่ระหว่างการเปลี่ยน server ส่ง `S2CGaugeSync` (ค่า + ความเร็ว) เฉพาะตอนแรงเอียงเปลี่ยน (ทุก 1–3.5 วินาที) ตอนกดหรือปล่อยปุ่ม ตอนกระตุก และ resync ทุก `gaugeResyncTicks` ระหว่างเคลื่อนที่ ประมาณ 2–3 packet/วินาทีต่อคนแบก ไม่มี packet ต่อ tick (D13)
- ~~**ยังไม่มี client prediction:** เข็มตอบสนองต่อปุ่มช้ากว่ากดเท่า ping~~ (แทนด้วย D57)
- **เข็มตอบสนองทันที (D57):** client ขยับเข็มเองทันทีที่กดหรือปล่อยปุ่ม (server ส่งความเร็วแบบไม่รวมปุ่ม + ความเร็วต่อปุ่ม `keyRate` มาใน `S2CGaugeSync`) server รับปุ่มแล้ว **นับย้อนไปครึ่ง ping** (`PatternContext.inputLagTicks`, ตัดที่ `maxPingGraceMs`) ค่าเข็มสองฝั่งจึงตรงกัน sync ที่มาถึงถูกเลื่อนไปข้างหน้าครึ่ง ping แล้ว ต่างไม่เกิน 0.12 ค่อยๆ เลื่อนเข้าหาใน 5 tick ต่างมากกว่านั้น (กระตุก, หก) กระโดดไปเลย server ยังเป็นคนตัดสินว่าหก ไม่มี packet เพิ่ม
- **ย่อเดิน (`Shift`):** นับเป็น "เดิน" ตามปกติ

- **แผนเผื่อใช้: บันได/เถาวัลย์** (ยังไม่ทำในรุ่นแรก, D52) ถ้าลองแล้วปีนง่ายเกินไป: session ตรวจ `ServerPlayer.onClimbable()` ทุก 5 tick แล้วให้ `PatternContext.motion()` คืน `CLIMB` (ต่อท้าย enum) pattern ส่ง **เอียง** หนึ่งครั้งทุก 2 บล็อกที่ปีนขึ้นหรือลง (นับจากความสูงสะสม) ฝั่งสลับซ้ายขวา กรอบเวลาเท่าแถว "เดิน" ไม่มีลมเล่น ระหว่างปีนไม่สุ่ม cue ปกติ ถ้ายังง่ายอยู่ค่อยเปลี่ยนเป็นห้ามปีน (ยกเลิกการเคลื่อนที่ขึ้นบน climbable ฝั่ง client + server ดึงกลับ)

## ผลลัพธ์และบทลงโทษ
session จบเมื่อวางลง ผลตัดสินจากระดับน้ำรวม (ซ้าย + ขวา) ตอนวาง เทียบกับตอนยก

| Outcome | เงื่อนไข |
| :--- | :--- |
| `PERFECT` | วางโดยน้ำไม่ลดเลย (และมีน้ำ > 0 ตอนยก) |
| `SUCCESS` | วางโดยยังมีน้ำเหลือ แต่หกไปบ้าง |
| `FAIL` | วางตอนถังว่างทั้งคู่ (และตอนยกมีน้ำ) |
| `ABORTED` | จบแบบผิดปกติ (ด้านล่าง) หรือยกหาบที่ว่างตั้งแต่แรก |

- **หกหนึ่งขั้น** (กดไม่ทัน, กดผิดฝั่ง, กดตอนลมเล่น, โดนตี): น้ำกระเซ็นจากขอบถังฝั่งนั้น (`SPLASH` + `FALLING_WATER`) และกระจายที่พื้นข้างเท้า พร้อมเสียงน้ำกระเซ็นเบาๆ ทุกคนใน 24 บล็อกเห็น (รวมคนแบก) ทำบน client จาก pose packet ที่ได้อยู่แล้ว ไม่มี packet เพิ่ม ไม่มี damage (ทำแล้ว 2026-11-02, `YokeVisuals.splash`)
- **ถังว่างทั้งคู่:** `effect(SLOWNESS, 100, 0)` หนึ่งครั้ง ("ไหล่ล้า") ไม่มีบทลงโทษใหญ่ เพราะเกมนี้เป็นกิจวัตร ไม่ใช่การทดสอบ
- **ไม่มีของรางวัล** (ไม่มี loot table) ผลลัพธ์ลง log และ scoreboard ตาม core หัวข้อ 12 และเพิ่ม `bhg_water_carried` (นับครั้งที่วางโดยมีน้ำ, **ยังไม่ได้ทำ**)
- **ทุบตรงๆ:** บล็อกไม่พัง (`BruteForce=KEEP`) ไม่มีบทลงโทษ admin ลบได้ในโหมด creative
- **จบแบบผิดปกติ** (ตาย, ออกเซิร์ฟ, เปลี่ยนมิติ, ถูก teleport ไกล, ว่ายน้ำ/หัวจม, ขึ้นพาหนะ, ใช้ elytra, มือมีของ, `/bhgame abort`): **หาบไม่หาย** วางบล็อกที่ตำแหน่งผู้เล่น (ระดับน้ำตามที่เหลือ) ถ้าวางไม่ได้ drop เป็น item ที่มี `BlockStateTag` ของระดับน้ำ ผลเป็น `ABORTED`

## การแสดงผล (vanilla ทางเดียว, D51)
ท่าแบกวาดด้วย model ของ vanilla เท่านั้น ไม่มี animation ของ Epic Fight

- **ลำตัวกับขา:** ท่าเดิน วิ่ง และกระโดดของ vanilla ตามปกติ **ลำตัวไม่เอียง**
- **คาน:** render layer วาดคานพาดบ่าหลังคอ หมุน (roll) รอบจุดหลังคอตามมุมเอียง
- **ถัง:** ห้อยจากปลายคานตรงลงพื้นเสมอ (ไม่หมุนตามคาน) ผิวน้ำในถังตามระดับน้ำของฝั่งนั้น ถังเต็มห้อยต่ำกว่าถังเบาเล็กน้อย
- **แขน:** สองมือจับคาน ตั้งมุมแขนที่ท้าย `PlayerModel.setupAnim` (mixin) ตามมุมคาน แขนฝั่งที่คานยกขึ้นยกตาม อีกฝั่งลดลง มือจึงอยู่บนคานตลอด
- **มุมเอียงคำนวณบนแต่ละ client เอง** จากจังหวะเดิน (`walkAnimation`) ความเร็ว การลงพื้น และระดับน้ำใน pose packet ไม่มี packet ต่อ tick (D13)
  - **น้ำเต็มสมดุล:** โยกน้อยมาก (เดินประมาณ 1.5° วิ่งประมาณ 3.5° ต่อก้าว) ถังแกว่งหน้าหลังเล็กน้อยตามก้าว และตามการเอียงของคานช้ากว่าเล็กน้อยแบบลูกตุ้ม
  - **หลังน้ำหก:** คานเริ่มสั่นแบบคนที่คอยแก้อยู่ตลอด แล้วค่อยๆ สงบลงในไม่กี่วินาที หกซ้ำระหว่างยังสั่นอยู่ = สั่นหนักขึ้น (ซ้อนได้ 2 ครั้ง)
  - **ถังไม่เท่ากัน:** คานห้อยไปทางถังที่หนักกว่า (ประมาณ 2° ต่อระดับที่ต่างกัน) และส่ายช้าๆ เหมือนกำลังหาจุดสมดุลตลอดเวลา
  - กระโดดลงพื้นยังเหวี่ยงเล็กน้อย (ปรับลดลง 2026-10-29 หลังลองในเกมแล้วโยกเกินไป)
- **การเอียงตามเข็ม (D55):** บนเครื่องคนแบก คานเอียงตามเข็มบนแถบ (ขอบแถบ = ประมาณ 14°) การโยกตามก้าวเป็นแค่พื้นหลัง
- ~~**การเอียงต้องตรงกับ cue (2026-10-29):** บนเครื่องคนแบก cue คือตัวกำหนดการเอียงหลัก ส่วนการโยกตามก้าวด้านบนเป็นแค่พื้นหลังเล็กๆ ไม่ให้มีการเอียงใหญ่ที่ไม่มี cue รองรับ (ผู้เล่นจะคิดว่าต้องกด)~~ (แทนด้วยแถบสมดุล D55)
  - **เอียง:** ตั้งแต่ cue เปิด (`leadTicks`) คานค่อยๆ เอียงลงฝั่งที่ตก มุมโตขึ้นจนถึงประมาณ 12° ตอนกรอบเวลาปิด กดถูก → คานดีดกลับตรงภายใน 3 tick พร้อมสั่นเล็กน้อยแบบเพิ่งรับไว้ได้ ไม่ทัน → เอียงสุดแล้วน้ำหก แล้วเข้าอาการสั่นหลังหก
  - **เอียงคู่ / ส่ายแรง:** เอียงฝั่งแรกแล้วเหวี่ยงไปอีกฝั่งตามจังหวะของ cue ตัวที่สอง
  - **ลมเล่น:** คานไม่เอียง มีแค่ผิวน้ำเป็นระลอกและถังสั่น (ตรงกับสเปกเดิม) จึงแยกออกจากเอียงได้ด้วยตา
  - ใช้กับทั้งมุมบุคคลที่หนึ่ง (BODY) และ model ของตัวเองในมุมบุคคลที่สาม ข้อมูลมาจาก cue ที่ client มีอยู่แล้ว ไม่มี packet เพิ่ม
  - prototype `/bhgame yoke` ยังไม่มี cue จึงยังเห็นแค่การโยกพื้นหลัง ต่อเข้ากับ cue ตอนทำ session จริง
  - **คนดู (D53):** รุ่นแรกยังไม่ได้รับ cue (D17) เห็นแค่การโยกพื้นหลัง การเซตอนหก และอาการสั่นหลังหก
  - **แผนเผื่อทำ: ให้คนดูเห็นการเอียงตาม cue** (ต้องแก้ D17 ก่อน) ส่งตารางเอียงล่วงหน้าเป็นชุดพร้อมกับตอนที่ส่ง cue ให้คนแบก (แต่ละรายการ 2 byte: อีกกี่ tick, ฝั่ง + องศา + เวลาค้าง) เฉพาะคนดูใน 16 บล็อก รวมของคนแบกหลายคนเป็น packet เดียวต่อคนดูต่อ tick ไม่ส่งลมเล่น การลงพื้น หรือการกดถูก (เครื่องคนดูดีดคานกลับเองเมื่อหมดเวลาค้าง น้ำหกมากับ pose packet) เครื่องคนดูทำ smooth เอง ประมาณ 0.3–0.5 packet/วินาทีต่อคนดู
- **ตอนหก:** pose packet ที่มีระดับน้ำใหม่ (ด้านล่าง) ทำให้ client ของคนดูเล่นท่า **เซ** ไปทางฝั่งที่ระดับน้ำลด (คานเหวี่ยงลงฝั่งนั้นแล้วกลับ ประมาณ 10 tick) พร้อม particle ไม่มี packet เพิ่ม (ตัวเลือก B ที่คุยกัน 2026-10-29)
- **Pose packet:** `S2CPlayerPose` สำหรับ `CARRY_YOKE` มีค่าเพิ่ม 1 byte (`water_left` 2 bit + `water_right` 2 bit) ส่งตอนเริ่มและตอนระดับน้ำเปลี่ยนเท่านั้น
- **Epic Fight:** ตอนยก บังคับผู้เล่นเป็นโหมด vanilla (`PlayerPatch.toVanillaMode`) และยกเลิก `ChangePlayerModeEvent` ของผู้เล่นคนนั้นจนกว่าจะวาง ทุก client ที่เห็นคนแบก (pose `CARRY_YOKE`) สั่ง `RenderEpicFightPlayerEvent.setShouldRender(false)` ให้ vanilla วาดแทน ตอนจบทุกทางคืนโหมดเดิม (ถ้าออกเซิร์ฟกลางคันแล้วค้างโหมด vanilla ยอมรับได้) **ยังไม่ได้ทดสอบว่าวิธีนี้ทำให้ vanilla วาดได้จริง ต้องทำ prototype ก่อน** ถ้าไม่ได้ ใช้ mixin ข้าม renderer ของ Epic Fight สำหรับผู้เล่นที่มี pose นี้ ทั้งหมดอยู่ใน `EpicFightClientBridge` และ class ฝั่ง server ของ compat ตาม D44
- **คนเล่นเห็น (มุมบุคคลที่หนึ่ง, diegetic):** คานพาดขวางด้านล่างจอแทนมือ ถังสองใบห้อยอยู่ขอบจอซ้ายขวา โยกเบาๆ ตามจังหวะก้าว **ไม่หมุนกล้อง**
  - เอียง: คานหมุนช้าๆ ไปทางฝั่งที่ตก (telegraph ตั้งแต่ `leadTicks`) ผิวน้ำเอียงตาม มือฝั่งที่ลอยขึ้นสั่นเล็กน้อยเป็นใบ้ว่าต้องกดฝั่งนี้
  - ส่ายแรง (หลังลงพื้น): คานยุบลงแล้วเหวี่ยงซ้ายขวา น้ำกระเพื่อมสูงกว่าเอียงปกติ
  - ลมเล่น: ระลอกบนผิวน้ำ + ใบไม้ปลิวผ่านหน้าจอหนึ่งใบ
  - กดถูก: คานกลับมาตรงทันที (feedback ฝั่ง client)
  - หก: น้ำกระฉอกออกจากถัง ระดับน้ำลดลงหนึ่งขั้น
- **ตัวสั่นในแดง (D70):** เครื่องคนแบกเท่านั้น คานสั่นเร็วๆ (แขนสั่นตาม) และภาพคานในมุมบุคคลที่หนึ่งสั่น แรงขึ้นตามความลึกในแดง แถบสมดุลสั่นด้วย ไม่หมุนกล้อง คนดูไม่เห็น (ไม่มี needle, D17)
- **HUD (D55):** แถบสมดุลบางๆ ~~เหนือตำแหน่ง hotbar~~ **ตรงตำแหน่ง hotbar** (hotbar ถูกซ่อนระหว่าง session อยู่แล้ว, 0.1.17: เดิมทับหลอดเลือด) มีขีดกลาง เข็มแดง ขอบสองข้างแดงจาง (ใกล้หก, ข้างละ 30% ตาม D70) ป้าย `LMB` / `RMB` ที่ปลายแถบ (ปิดได้ด้วย `showKeyHints`) ไม่มีตัวเลข เห็นเฉพาะคนเล่น
- **เสียง (เฉพาะคนเล่น):** ไม้คานลั่นเอี๊ยดตอนเอียง, น้ำกระฉอกตอนลงพื้น, ลมหวีดตอนลมเล่น
- **ย่อตัว (D56):** คานเอียงไปกับไหล่ แต่ถังยังห้อยตรงลงพื้น
- **หน้าตาตอนแบก (2026-11-02):** texture ของ mod เอง `textures/entity/water_yoke.png` (คานไม้สีน้ำตาลเข้ม, เชือก, ถังไม้สีอ่อนมีห่วงเหล็กสองเส้น, น้ำสีฟ้า) แทน texture ของ vanilla ที่ยืดผิดขนาดจนเป็นสีเทา (ภาพ placeholder วาดด้วยสคริปต์ รอ P6)
- **คนภายนอกเห็น:** ผู้เล่นแบกคานหาบเดินไปมา คานโยกตามก้าว เซเมื่อน้ำหก ระดับน้ำในถังแต่ละใบลดลงเมื่อหก ตอนยกและวางเห็นท่าย่อตัว ไม่เห็น cue (D17)
- **bhfx / fallback:** ไม่ใช้

  - คลิกขวาบล็อกฝึกด้วยมือเปล่า (ไม่ว่ากด Shift หรือไม่) → เรียก `use` ของบล็อกเองแล้วยกเลิก event Carry On จึงไม่มีโอกาสยก แม้ tag จะโดน datapack เขียนทับ
  - ผู้เล่นที่อยู่ใน session (รวม `/bhgame yoke`) คลิกบล็อกหรือ entity ฝั่งเซิร์ฟไม่ได้ ปิดช่องหนึ่ง ping หลังยกหาบที่ client ยังไม่รู้ว่าเริ่ม session และยังค้างคลิกขวาอยู่ (Carry On จะยกบล็อกข้างหลังขึ้นมาซ้อน)
  - ผู้เล่นอื่นมือเปล่ายกคนที่อยู่ใน session ไม่ได้ (เซิร์ฟตั้ง `pickupPlayers = true`)
  - คนที่ Carry On แบกของอยู่ → ไม่แตะ ปล่อยให้ Carry On วางของ จึงไม่มีทางแบกสองอย่างพร้อมกัน (`CarryOnCompat.isCarrying` เรียก `CarryOnDataManager.getCarryData(..).isCarrying()` ด้วย MethodHandle ไม่ import Carry On ถ้า API เปลี่ยนถือว่าไม่ได้แบก)
- tag `bhgame:no_carry` ขาด `qi_station` มาตั้งแต่เพิ่มเกมนั้น เติมแล้วใน 0.1.22
