# หญ้าเกี่ยวรากคู่ (`twin_grass`)

**สถานะ:** 🔨 เขียนโค้ดแล้ว (2026-10-19, P2a, D35) ยังไม่ได้ทดสอบในเกม ภาพยังเป็นแบบชั่วคราว (texture `crimson_roots`, แสงสีเดียวกันทั้งสองฝั่ง ต่างกันแค่ความสว่าง)

## แนวคิด
หญ้าที่รากสองสายพันกันอยู่ใต้ดิน ถ้าดึงฝั่งเดียวรากอีกฝั่งจะขาด **ต้องมีสองคนคุกเข่าคนละฝั่งแล้วดึงให้สัมพันธ์กัน** คนหนึ่งคุมรากหยาง (`LMB`) อีกคนคุมรากหยิน (`RMB`) ฝึกการประสานลมปราณกับคู่ฝึก และเป็นฉากโรลเพลที่คนภายนอกเห็นแล้วเข้าใจทันที (ศิษย์สองคนช่วยกันถอนหญ้า)

## รูปแบบ
- **ประเภท:** Herb (ใช้ครั้งเดียว), **ผู้เล่น 2 คน**
- **หน้าตาบล็อก:** กอหญ้าสองต้นที่โคนพันกัน
- **ปุ่ม:** คนแรกที่คลิก = `LMB` (หยาง), คนที่สอง = `RMB` (หยิน) แต่ละคนกดได้แค่ปุ่มของตัวเอง
- **ค่าเริ่มต้น:** `MaxHP` = 10 (ใช้ร่วมกัน), `MaxMistakes` = 4 (นับรวมทั้งคู่)
- **Input profile:** ต่อคน: หยาง `locked(LMB).withIdlePresses()`, หยิน `locked(RMB).withIdlePresses()`
- **Channel:** `BLOCK` (แต่ละคนเห็นแสงของรากฝั่งตัวเองชัด และเห็นของคู่หูจางๆ เพื่อจับจังหวะกัน)
- **ท่าทางที่คนภายนอกเห็น:** `PULL_HERB` ทั้งสองคน
- **คำใบ้ตอนเริ่ม:**
  - คนแรก: "รากนี้พันกันอยู่สองสาย… ต้องมีใครอีกคนจับอีกฝั่ง"
  - เมื่อครบสองคน: "ดึงตอนรากฝั่งเจ้าสว่าง ถ้าสว่างทั้งสองฝั่ง ต้องดึงพร้อมกัน"

## การเข้าร่วม (lobby)
1. คนแรกคลิกขวา → คุกเข่า (pose) แต่ยังไม่เริ่ม สถานะ `WAITING` รอได้ 30 วินาที กดยกเลิกได้ตามปกติ
2. คนที่สองคลิกขวา (ต้องอยู่ใน `startReach` ด้วย, ฝั่งไหนก็ได้ ดูคำถามเปิดข้อ 2) → เริ่ม `FOCUS` พร้อมกันทั้งคู่
3. คนที่สามคลิก → ขึ้นข้อความว่ามีคนกำลังใช้อยู่
4. หมดเวลารอ → จบแบบ `ABORTED` ไม่มีบทลงโทษ หญ้ายังอยู่

## Pattern
| Phase | เงื่อนไข | Cue | กรอบเวลา (Difficulty 1 / 2 / 3) |
| :--- | :--- | :--- | :--- |
| 1 | HP > 60% | `TAP` ทีละฝั่ง สลับกันไปมา (หยาง → หยิน → หยาง) | 10 / 8 / 6 tick |
| 2 | HP ≤ 60% | สุ่ม: ฝั่งเดียว, **คู่** (สว่างทั้งสองฝั่ง ต้องกดภายในกรอบเดียวกันทั้งคู่ ถึงนับ hit), สองครั้งติดฝั่งเดียว | 8 / 6 / 5 tick |
| 3 | HP ≤ 25% | เพิ่ม `FEINT`: รากฝั่งหนึ่งกะพริบหลอก คนฝั่งนั้นต้องไม่กด | 8 / 6 / 5 tick |

- cue **คู่** ถ้ากดแค่คนเดียว = พลาด (ของคนที่ไม่กด)
- กดตอนรากฝั่งตัวเองมืด = พลาดของคนนั้น (หนึ่งครั้งต่อช่วงมืด เหมือนหญ้าชีพจร)
- ความยากอยู่ที่การ **ฟังจังหวะคู่หู** ไม่ใช่แค่ความเร็ว: cue คู่ในระดับสูงมาไม่ตรงจังหวะเดิมของแต่ละฝั่ง

## บทลงโทษ
- **พลาดหนึ่งครั้ง:** โดนเฉพาะคนที่พลาด (Poison สั้นๆ แบบหญ้าชีพจร) ทั้งคู่เห็นรากฝั่งนั้นกระตุก
- **FAIL:** รากขาด บทลงโทษใหญ่ **ทั้งสองคน** (ในเรื่องคือพลังตีกลับทั้งคู่)
- **ทุบตรงๆ:** บทลงโทษใหญ่กับคนทุบ (ตาม D19)
- คนหนึ่งยกเลิก, ออกเซิร์ฟ หรือตายกลางคัน → session จบแบบ `FAIL` สำหรับ **คนที่ทิ้ง** (บทลงโทษใหญ่) และ `ABORTED` สำหรับคนที่เหลือ (ไม่มีบทลงโทษ หญ้าหายไป) **ผู้ใช้ตัดสินแล้ว 2026-10-19** (D32)
  - ออกเซิร์ฟกลางคัน: ผู้เล่นไม่อยู่แล้วจึงใส่ effect ไม่ได้ บันทึก `FAIL` ใน `Stats` อย่างเดียว ไม่เก็บบทลงโทษค้างไว้รอตอนกลับเข้ามา (ไม่ต้องเก็บข้อมูลค้างใน memory)
  - ช่วง `WAITING` (ยังรอคนที่สอง) ยกเลิกได้ฟรีเสมอ

## รางวัล
- loot table เดียว drop ที่บล็อก (ในเรื่องคือหญ้าทั้งต้น ทั้งสองคนตกลงแบ่งกันเอง ซึ่งเป็นโรลเพลด้วย)
- `perfect` เมื่อทั้งคู่ไม่พลาดเลย

## การแสดงผล
- **คนเล่นเห็น:** ต้นหยางเรืองสีขาวทอง ต้นหยินเรืองสีม่วงคราม ฝั่งของตัวเองสว่างชัด ฝั่งคู่หูจาง แท่งรากสูงตาม HP ที่ใช้ร่วมกัน
- **เสียง (เฉพาะคนเล่นทั้งสอง):** เสียงหัวใจของฝั่งตัวเอง + เสียงเบาๆ ตอน cue คู่
- **คนภายนอกเห็น:** สองคนคุกเข่าคนละฝั่งดึงหญ้าต้นเดียวกัน และผลลัพธ์

## ผลต่อ core (ดู D31)
- session มี **ผู้เข้าร่วมหลายคน** แต่ละคนมี role (`InputProfile` ของตัวเอง) แต่ HP และ pattern ใช้ร่วมกัน
- `SessionState.WAITING` สำหรับ lobby
- `CueData` ต้องบอกว่า cue เป็นของ role ไหน (หรือ cue คู่ = ทุก role) ฝั่ง client ใช้วาดความสว่างของตัวเองกับของคู่หู
- `onInput` รู้ว่าใครกด, `miss()` รู้ว่าใครพลาด
- packet ต่อ session เพิ่มเป็นประมาณ 2 เท่า (ส่งให้สองคน) แต่จำนวน session ลดลงครึ่งหนึ่งสำหรับคนเท่ากัน จึงไม่กระทบงบใน `multiplayer-performance.md`
