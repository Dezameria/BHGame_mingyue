# กลไกกลาง (Core Mechanics)

กฎในไฟล์นี้ใช้กับทุกมินิเกม สเปกของแต่ละเกมใน [`minigames/`](minigames/) กำหนดได้แค่ค่า, pattern, input profile และ cue channel ของตัวเอง ถ้าเกมไหนต้องการกฎใหม่ ให้เพิ่มกฎที่นี่ก่อน (และบันทึกใน [`../decisions.md`](../decisions.md))

## 0. Immersion มาก่อน

มินิเกมต้อง **ไม่ดูเป็นเกม** ในสายตาคนอื่น และรบกวนการโรลเพลให้น้อยที่สุด

- **ตัววัตถุเป็นบล็อกธรรมดาในโลก** เหมือนดอกไม้ กล่อง หรือหุ่นไม้ คลิกขวาเพื่อเริ่ม ไม่มีป้ายชื่อ ไม่มีแถบ HP ไม่มีตัวเลขลอย
- **คนภายนอกเห็นแค่สิ่งที่เกิดขึ้นจริงในเรื่อง** คือท่าทางของผู้เล่น (ถอนหญ้า, ซ้อมกับหุ่น, นั่งปิดตา, ดีดนิ้วใส่เทียน) และผลที่ตามมา ไม่เห็น cue ไม่เห็น HUD
- **คนเล่นเห็น gameplay** แต่ cue ส่วนใหญ่แสดง **บนวัตถุในโลก** (diegetic) และ render เฉพาะบน client ของคนเล่น HUD บนจอมีน้อยที่สุด ดูหัวข้อ 9

## 1. ทุกอย่างมี HP + Pattern (ภายในเท่านั้น)

- **HP** = จำนวนครั้งที่ต้องทำสำเร็จ (กดถูกหนึ่งจังหวะ, ผ่านหนึ่งชุดลูกศร, ดับเทียนหนึ่งเล่ม) HP ถึง 0 = ชนะ
  - **HP เป็นค่าภายในของ session ไม่แสดงเป็นแถบหรือตัวเลข** คนเล่นรับรู้ผ่านตัววัตถุ เช่น หญ้าค่อยๆ ถูกดึงขึ้นจากดิน, เทียนที่ดับแล้วมีควันลอย
- **Pattern** = logic ฝั่ง server ที่ตัดสินว่าจะส่ง cue อะไรเมื่อไร ขึ้นกับ phase (HP ที่เหลือ) และ difficulty
- **Gauge** ใช้แทนหรือควบคู่กับ HP ได้ (หัวข้อ 5)
- **เวลาจำกัด** (`TimeLimit`, ไม่บังคับ): ถ้าตั้งไว้แล้วหมดเวลาก่อน HP ถึง 0 = `FAIL`

## 2. ปุ่ม (InputKey)

| Key | ปุ่มจริง | ความหมายทั่วไป |
| :--- | :--- | :--- |
| `LMB` | คลิกซ้าย | ดึง / ปราณหยาง / ปัดซ้าย / ดีดนิ้ว |
| `RMB` | คลิกขวา | ปราณหยิน / ปัดขวา |
| `SPACE` | Space (keybind jump) | ปัดป้อง / หลบขึ้น |
| `UP` `LEFT` `DOWN` `RIGHT` | W A S D (keybind เดิน) | ทิศทาง |

- อ่านจาก keybind ของผู้เล่น (ไม่ fix ตัวอักษร)
- ทิศเฉียง = กดสองปุ่มพร้อมกันภายใน `chordWindowMs` (ค่าเริ่มต้น 100ms)

## 3. Input profile (ต่อเกม)

แต่ละเกมประกาศ input profile ของตัวเอง client ใช้ค่านี้ตัดสินว่าจะล็อกอะไรและส่งอะไร

| ค่า | ความหมาย | ค่าที่ใช้บ่อย |
| :--- | :--- | :--- |
| `keys` | ปุ่มที่ดักมาใช้ในเกม (ปุ่มอื่นของ Minecraft ถูกล็อกเฉยๆ) | ต่อเกม |
| `holdKeys` | ปุ่มที่เป็นแบบค้าง ส่งตอนปล่อยด้วย ปุ่มอื่นส่งแค่ตอนกด | หญ้าอสุนีบาต: `LMB` |
| `camera` | `LOCKED` (หันเข้าหาวัตถุแล้วล็อก) / `FREE` (หมุนได้ แต่เดินไม่ได้) | ทุกเกม `LOCKED` ยกเว้นดับเทียนและหาบน้ำ |
| `crosshair` | แสดง crosshair ไหม | เฉพาะดับเทียน |
| `sendIdlePresses` | ส่งการกดที่เกิดตอนไม่มี cue ไหม (ถ้าไม่ส่ง client ทิ้งเอง) | `true` เฉพาะเกมที่ช่วงว่างเป็น FEINT (หญ้าชีพจร) |
| `aimPayload` | แนบทิศที่มองไปกับ input | เฉพาะดับเทียน |
| `movement` | `LOCKED` (ค่าเริ่มต้น) / `FREE` (เดิน วิ่ง และกระโดดตามปกติ) (D48–D50, ยังไม่มีโค้ด) | `FREE` เฉพาะหาบน้ำ |

ทุก profile ล็อกการเดินเสมอ ยกเว้น `movement=FREE` และซ่อน HUD vanilla (hotbar, หลอด XP, และ crosshair ถ้า `crosshair=false`)

## 4. ชนิดของ cue และ channel

### ชนิด (ผู้เล่นต้องทำอะไร)

| ชนิด | ผู้เล่นต้องทำ | ถือว่าพลาดเมื่อ |
| :--- | :--- | :--- |
| `TAP` | กดปุ่มที่กำหนดภายในกรอบเวลา | ไม่กดทัน หรือกดผิดปุ่ม |
| `HOLD` | กดค้างจนครบเวลา หรือจนกว่า pattern จะบอกให้ปล่อย | ปล่อยก่อนเวลา หรือค้างตอนที่ห้าม |
| `FEINT` | **ห้ามกด** (cue หลอก) | กดปุ่มใดๆ ระหว่าง cue นี้ |
| `AIM` | หันไปที่เป้าที่กำหนดแล้วกดปุ่มภายในกรอบเวลา | ไม่ทัน (การยิงพลาดเป้าไม่นับเป็น mistake แต่เสียเวลา) |
| `SEQUENCE` | กดชุดปุ่มตามลำดับให้ครบก่อนหมดเวลา | หมดเวลา (กดผิดกลางชุด = เริ่มชุดใหม่ เวลาเดินต่อ) |

cue หนึ่งตัวมี: `type`, `keys` (หรือลำดับปุ่มสำหรับ `SEQUENCE`), `windowTicks`, `damage` (HP ที่ลดเมื่อสำเร็จ ค่าเริ่มต้น 1), `channel`, `visual`, `target` (สำหรับ `AIM`) และ `sound` (ไม่บังคับ)

### Channel (cue แสดงที่ไหน)

| Channel | แสดงที่ | ใช้กับ |
| :--- | :--- | :--- |
| `BLOCK` | บนตัวบล็อกที่คลิก (แสง, สี, ประกาย, การขยับ) | หญ้าทุกชนิด |
| `WORLD_ARROW` | ลายพู่กันลูกศรลอยในโลกข้างวัตถุ + ส่วนของวัตถุที่เรืองตามทิศ | หุ่นไม้, หญ้าพันราก |
| `WORLD_TARGET` | บนเป้าในโลกที่อยู่รอบตัว (ตำแหน่งจาก target set ของ session) | ดับเทียน |
| `SPATIAL_AUDIO` | เสียงที่มาจากทิศหนึ่งรอบตัวผู้เล่น ไม่มีภาพ | ฟังลม |

ทุก channel วาดเฉพาะบน client ของคนเล่น

## 5. Gauge

ค่าภายใน 0.0–1.0 แต่ละเกมมีได้ไม่เกิน 3 อัน (เช่น ความร้อนของ `fire_root`, ความคืบหน้าการดึงของ `thunder_grass`) **การแสดงผลต้องเป็นแบบ diegetic ก่อน** ถ้าจำเป็นต้องมีบนจอ ใช้แถบลายพู่กันบางๆ ที่ไม่มีตัวเลข

## 6. Target set

เกมที่ใช้ `WORLD_TARGET` จะสร้าง **target set** ตอนเริ่ม session คือรายการตำแหน่งในโลก (สูงสุด 32 ตำแหน่ง) ส่งให้ client ครั้งเดียวใน `S2CSessionStart` แล้ว cue อ้างถึงเป้าด้วย index ไม่ส่งพิกัดซ้ำ วิธีหาเป้าเป็นของแต่ละเกม (ดับเทียน: สแกนหาเทียนที่ admin วาง)

## 7. Mistake, Outcome และบทลงโทษ

- **พลาดหนึ่งครั้ง** = mistake +1 และได้ **บทลงโทษเล็ก** (กำหนดต่อเกม และไม่มีก็ได้) คนเล่นรับรู้จากตัววัตถุและเสียง ไม่มีตัวนับบนจอ
- **mistake ครบ `MaxMistakes`** (ค่าเริ่มต้น 3) หรือหมด `TimeLimit` หรือ gauge แพ้ = `FAIL` และได้ **บทลงโทษใหญ่**

| Outcome | เงื่อนไข | หญ้า (Herb) | แท่นฝึก (Station) |
| :--- | :--- | :--- | :--- |
| `PERFECT` | ชนะโดยไม่พลาดเลย | drop loot table `perfect` แล้วบล็อกหายไป | drop `perfect` (ถ้าตั้งไว้) แล้วรีเซ็ต |
| `SUCCESS` | ชนะแต่มีพลาดบ้าง | drop loot table `normal` แล้วบล็อกหายไป | drop `normal` (ถ้าตั้งไว้) แล้วรีเซ็ต |
| `FAIL` | ดูด้านบน | บทลงโทษใหญ่ หญ้าพัง ไม่ drop อะไร | บทลงโทษใหญ่ แล้วรีเซ็ต |
| `ABORTED` | ผู้เล่นออกเกม, ตาย, กดยกเลิก, บล็อกหายไป | หญ้ายังอยู่ | รีเซ็ต |

ของรางวัลเด้งออกมาจากตำแหน่งวัตถุเป็น item ตามปกติ (เหมือนเก็บดอกไม้)

### บทลงโทษโดนเฉพาะคนเล่นเสมอ

**บทลงโทษที่ใช้ได้:** `effect(MobEffect, ticks, amplifier)`, `damage(amount)`, `fire(seconds)`, `freeze(ticks)`, `knockback(strength)`, `burst(power)`, `strikeVisual()`

- `burst` คือ **ระเบิดปลอม:** damage และ knockback ใส่คนเล่นคนเดียว + เสียงและ particle ขนาดเล็ก **ห้ามใช้ `Level.explode`** เพราะจะทำคนยืนดูบาดเจ็บ และคำนวณใส่ entity ทุกตัวรอบๆ
- `strikeVisual` คือ **ฟ้าผ่าปลอม:** เอฟเฟกต์สายฟ้าระยะใกล้ (particle + เสียง) **ห้าม spawn `LightningBolt`** เพราะจะถูก track ไกลมาก และอาจทำให้ไฟไหม้หรือโดนคนอื่น
- คนรอบข้างเห็นผล (ผู้เล่นสะดุ้ง, ไฟลุก, ประกายสั้นๆ) ซึ่งตั้งใจไว้ แต่ไม่มีใครอื่นได้รับผลกระทบ
- particle ของบทลงโทษจำกัดจำนวนและระยะ ([`../multiplayer-performance.md`](../multiplayer-performance.md))

## 8. ทุบตรงๆ (brute force)

- **ความแข็ง:** บล็อกต้องใช้เวลาทุบด้วยมือประมาณ 1.5 วินาที **ไม่แตกในคลิกเดียวแบบดอกไม้** กันคนที่เผลอคลิกซ้ายแทนคลิกขวา
- **ตอนเริ่มทุบ:** ขึ้นข้อความใน action bar เช่น "รากยังยึดแน่น… ฝืนดึงจะขาด" คนที่ทุบต่อจนแตกจึงเป็นการตั้งใจ
- **ผล:**
  - **หญ้า:** พัง ไม่ drop ของ และผู้เล่นโดน **บทลงโทษใหญ่ของเกมนั้น**
  - **แท่นฝึก:** ไม่พัง (ทุบไปก็ไม่คืบ) และโดนบทลงโทษเล็กของเกมนั้น (ถ้ามี)
- ปรับได้ต่อบล็อกด้วย NBT `BruteForce`: `DESTROY` (ค่าเริ่มต้นของหญ้า) / `KEEP` (ค่าเริ่มต้นของแท่นฝึก)
- ผู้เล่นโหมด creative ทุบได้ทันทีโดยไม่โดนอะไร (สำหรับ admin ลบ)
- บล็อกทนระเบิด, ลูกสูบดันไม่ได้, น้ำและลาวาทำให้หลุดไม่ได้

## 9. สิ่งที่แต่ละคนเห็น

| | คนเล่น | คนภายนอก |
| :--- | :--- | :--- |
| ท่าทางของผู้เล่น | มุมมองบุคคลที่หนึ่ง | animation แบบ loop ช้าๆ ที่ไม่สะท้อนการกดปุ่ม ([`../integrations/playeranim.md`](../integrations/playeranim.md)) |
| ของประกอบบนตัวผู้เล่น (เช่น ผ้าปิดตา) | ไม่เห็น | **เห็น** (layer ฝั่ง client จากสถานะ pose ไม่มี packet เพิ่ม) |
| cue ทุก channel | เห็น/ได้ยิน | **ไม่เห็น ไม่ได้ยิน** |
| ความคืบหน้าบนวัตถุ | เห็น | ไม่เห็น (วัตถุนิ่งเหมือนเดิม) |
| เสียงบรรยากาศ (ใบไม้เสียดสี, ไม้กระทบ) | ได้ยิน | ได้ยินเบาๆ |
| บทลงโทษและผลลัพธ์ | เห็น | **เห็น** |
| HUD บนจอ | น้อยที่สุด | ไม่เห็น |

**HUD ของคนเล่น:**
- คำใบ้ปุ่ม (ไอคอน LMB/RMB/Space เล็กๆ) แสดงเมื่อเปิด client config `showKeyHints` (ค่าเริ่มต้น เปิด)
- crosshair แสดงเฉพาะเกมที่ input profile กำหนด
- ไม่มีแถบ HP, ตัวนับ หรือตัวเลขใดๆ

## 10. กฎของ session

- ผู้เล่นหนึ่งคนอยู่ได้ทีละหนึ่ง session, บล็อกหนึ่งอันเล่นได้ทีละหนึ่งคน (คนอื่นคลิกจะขึ้นข้อความใน action bar ว่ามีคนกำลังใช้อยู่)
- **ระยะเริ่ม (D30):** ต้องเดินเข้าไปถึงตัววัตถุก่อน ไม่ใช่แค่อยู่ในระยะ reach ของ vanilla วัดระยะแนวราบจากเท้าถึงกลางบล็อก (`TrainingBlock.startReach()`) และระยะแนวดิ่งจากเท้าถึงฐานบล็อก (`startHeightTolerance()`) ถ้าไกลเกิน action bar ขึ้นว่า "ต้องเข้าไปให้ถึงตัวก่อน"
  - หญ้า: แนวราบ 1.75 บล็อก (ยืนบนบล็อกที่ติดกัน รวมแนวทแยง), แนวดิ่ง 1 บล็อก
  - แท่นฝึก: ค่าเริ่มต้น 3 บล็อก / 1.5 บล็อก (แต่ละเกมปรับได้)
  - ระหว่าง session ใช้ระยะ `MAX_DISTANCE` (6 บล็อก) ตามเดิม (ยกเว้นบล็อกแบบ Carry ที่ไม่มีบล็อกยึด ดูด้านล่าง)
- **บล็อกแบบ Carry (D48, ยังไม่มีโค้ด):** บล็อกถูกยกออกจากโลกตอนเริ่มและวางคืนตอนจบ session ไม่มีบล็อกยึด จึงไม่เช็กระยะและไม่ abort เมื่อบล็อกหาย จบผิดปกติทุกทางต้องวางบล็อกคืนหรือ drop เป็น item ห้ามให้ของหาย ดู [`minigames/water_yoke.md`](minigames/water_yoke.md) ถ้าเกิน session ถูกยกเลิก (ผู้เล่นเดินไม่ได้อยู่แล้ว จึงเกิดจากการโดนผลักหรือ teleport เท่านั้น)
- **เริ่ม:** กล้องหันเข้าหาวัตถุอย่างนุ่มนวล (ประมาณ 0.5 วินาที, ยกเว้น `camera=FREE`) แล้วเข้าช่วงตั้งสมาธิ 2 วินาที (`FOCUS`) ไม่มีเลขนับถอยหลัง ระหว่างนี้ action bar ขึ้น **คำใบ้แบบในเรื่อง** หนึ่งบรรทัด (กำหนดต่อเกม เช่น "หญ้านี้หายใจเป็นจังหวะ… รอให้มันผ่อนลมออก")
- **ยกเลิก session** เมื่อ: ผู้เล่นกดปุ่มยกเลิก (keybind ค่าเริ่มต้น `Backspace`), ออกจากเซิร์ฟ, ตาย, เปลี่ยน dimension, บล็อกถูกลบ หรือ admin ใช้ `/bhgame abort`
- **เกมหลายคน (D31, D32):**
  - คนแรกที่คลิกได้ role 0 คนถัดไปได้ role 1 แต่ละ role มีปุ่มของตัวเอง HP ใช้ร่วมกัน ส่วน mistake นับรวมทุกคน (บทลงโทษเล็กโดนเฉพาะคนที่พลาด)
  - ระหว่างรอคู่ (`WAITING`) คนแรกคุกเข่าอยู่กับที่และขยับไม่ได้ รอได้ `partnerWaitTicks` (30 วินาที) ไม่มีใครมา = ยกเลิกเฉยๆ ขึ้นข้อความ "ไม่มีใครมาจับอีกฝั่ง"
  - ยกเลิกระหว่างรอไม่มีบทลงโทษ แต่หลังเริ่มแล้ว คนที่ออก (กดยกเลิก, ตาย, ออกเซิร์ฟ, เดินออกนอกระยะ) ได้ `FAIL` + บทลงโทษใหญ่ คนที่เหลือได้ `ABORTED` + ข้อความว่าคู่ฝึกปล่อยมือ บล็อกถือว่าเสีย (หญ้าหายไป) ถ้าออกเซิร์ฟจะบันทึกแค่สถิติ
  - client แต่ละคนเห็น cue ของ role ตัวเองชัด และของคู่หูจางๆ (35%) เพื่อจับจังหวะกัน
- เปิดเมนู pause ไม่ยกเลิก session (บนเซิร์ฟเกมไม่หยุด cue จึงพลาดไปตามปกติ)
- **หลังจบ:** ไม่รับ input ของโลก (ตี, ใช้ของ) 10 tick กันคลิกที่ค้างอยู่ไปทุบบล็อกข้างๆ
- ผลลัพธ์แจ้งเฉพาะคนเล่นทาง action bar ด้วยถ้อยคำในเรื่อง ไม่ประกาศในแชท

## 11. การตั้งค่าของ admin (NBT ของบล็อก)

| NBT | ค่าเริ่มต้น | ความหมาย |
| :--- | :--- | :--- |
| `MaxHP` | ต่อเกม | HP เริ่มต้น |
| `Difficulty` | `1` | 1–3 ยิ่งสูง กรอบเวลายิ่งแคบและ cue ยิ่งเร็ว |
| `MaxMistakes` | `3` | พลาดได้กี่ครั้ง |
| `TimeLimit` | ไม่มี | วินาที (ไม่บังคับ) |
| `LootPerfect` | `bhgame:minigames/<id>/perfect` | loot table ตอนได้ `PERFECT` |
| `LootNormal` | `bhgame:minigames/<id>/normal` | loot table ตอนได้ `SUCCESS` |
| `BruteForce` | `DESTROY` (หญ้า) / `KEEP` (แท่นฝึก) | ดูหัวข้อ 8 |

บางเกมมี NBT เพิ่มเอง (เช่น `Radius` ของดับเทียน) ดูในสเปกของเกมนั้น

**การวาง:** วางจาก inventory ในโหมด creative เหมือนบล็อกทั่วไป หรือ `/setblock` พร้อม NBT
ตัวอย่าง: `/setblock ~ ~ ~ bhgame:pulse_grass{Difficulty:2,MaxHP:10,LootPerfect:"myserver:rare_herb"}`
item ที่ตั้งค่าไว้ล่วงหน้า: `/give @s bhgame:pulse_grass{BlockEntityTag:{Difficulty:2}}`

## 12. การตรวจผล

ทุกครั้งที่ session จบ (รวมการทุบตรงๆ):
- เขียนลง server log: `[bhgame] <player> <game_id> <outcome> mistakes=<n> time=<s>s at <pos>`
- บวกค่าใน scoreboard objective: `bhg_perfect`, `bhg_success` และ `bhg_fail` (สร้างให้อัตโนมัติถ้ายังไม่มี)
- admin ใช้ `/bhgame stats <player>` ดูสรุปได้

## 13. ความแฟร์ของจังหวะ

- server เป็นคนสร้าง cue และตัดสินผล ส่วน client มีหน้าที่แค่แสดงผลและส่ง input
- server ส่ง cue **ล่วงหน้า** `leadTicks` (ค่าเริ่มต้น 6 tick) ให้ client แสดง telegraph ก่อนกรอบเปิด คนที่ ping สูงจึงเห็น cue ตรงเวลา
- กรอบเวลาฝั่ง server = `windowTicks` + `pingGrace` (คิดจาก latency ของผู้เล่น จำกัดไม่เกิน `maxPingGraceMs` ค่าเริ่มต้น 250ms)
- เวลาทั้งหมดฝั่ง server นับเป็น tick ไม่ใช้เวลาจริง ถ้าเซิร์ฟ lag ทุกอย่างช้าลงพร้อมกัน ไม่ใช่พลาดเพราะ lag
- 1 tick = 50ms การตั้ง `windowTicks` ห้ามต่ำกว่า 4 tick (200ms)
- รายละเอียดทั้งหมดดู [`../multiplayer-performance.md`](../multiplayer-performance.md)
